# 資料請求／送付 自動通知 セットアップ手順（アド・クリックス様）

コール状況の列に「資料請求」または「資料送付」が入力されたら、その行の情報を
LINE・メール・Slack に自動で飛ばす仕組みです。届け先ごとに中身を出し分けます。

- **LINE（クライアント様のグループ）**：企業名・住所・電話番号だけ（スッキリ）
- **メール／Slack（社内）**：上記＋シート名・行番号（追跡用）

対象シート：「リスト（寺社仏閣）」「リスト（社福）」
引き金キーワード：「資料請求」「資料送付」（どちらでも通知）

---

## 全体の流れ（かんたん順）

1. スクリプトを貼り付ける（5分）
2. **メール＋Slack を先に有効化**（各5分・設定したら即動きます）
3. トリガーを作る（`setupTrigger` を1回実行）
4. `testNotify` で動作確認
5. **LINE は最後に**（Messaging API の設定が必要なので）

> おすすめ：LINE は設定の関門があるので、まずメール＋Slack を動かして
> 「報告漏れゼロ」を今日から実現 → 裏で LINE を整えるのが安全です。

---

## STEP 1. スクリプトを貼り付ける

1. 対象のスプレッドシートを開く
2. 上メニュー **拡張機能 → Apps Script**
3. エディタの中身を全部消して、`資料請求通知_GAS.js` の中身を丸ごと貼り付け
4. フロッピーのアイコンで保存

## STEP 2. CONFIG（設定）を埋める

コード上部の `CONFIG` の `★` の箇所を埋めます。

- `HEADERS`：実際のシートの見出しと**1文字も違わない**ように合わせる
  （「企業名」「住所」「電話番号」「コール状況」）。違うと空欄になります。
- `EMAIL.to`：クライアント様＋社内のアドレスを配列で（複数OK）
- `SLACK.webhookUrl`：STEP 3 で発行するURL
- `ADMIN_EMAIL`：不具合時にお知らせが届く社内アドレス
- `LINE`：いまは触らなくてOK（`enabled: false` のまま）

### （任意）二重通知を防ぐ
シートに **「通知日時」** という見出しの列を1つ足すと、同じ行への再編集で
二重に飛ぶのを防げます（通知した行に日時が記録され、以後スキップ）。無くても動きます。

## STEP 3. Slack の受け取り口（Incoming Webhook）を作る

1. https://api.slack.com/apps → **Create New App → From scratch**
2. アプリ名（例：資料請求通知）とワークスペースを選ぶ
3. 左メニュー **Incoming Webhooks** を **On**
4. **Add New Webhook to Workspace** → 投稿先に **Pj-アドクリックス** を選ぶ
5. 発行された `https://hooks.slack.com/...` を `CONFIG.SLACK.webhookUrl` に貼る

## STEP 4. トリガーを作る（1回だけ）

1. Apps Script エディタ上部の関数選択で **`setupTrigger`** を選び ▶ 実行
2. 初回は Google の権限確認が出ます → 自分のアカウントで **許可**
   （「安全ではないページ」と出たら「詳細 → （プロジェクト名）に移動」で進めます）
3. 「通知トリガーを設定しました」とスプシ右下に出れば成功

> ※ メール送信や外部通知には、この「インストール型トリガー」が必須です
>   （シート標準の onEdit では権限の都合で送信できません）。

## STEP 5. 動作確認

1. 関数選択で **`testNotify`** を選び ▶ 実行 → メール・Slack にテストが届くか確認
2. OKなら、実際に対象シートのコール状況へ「資料送付」と入れてみて、届くか確認

---

## STEP 6. LINE を有効化する（Messaging API・最後に）

> 現在「Messaging API が使えるか不明／未設定」なので、順に進めます。
> 届け先は **クライアント様とのグループ**（アポインターが取った資料送付を
> クライアント様へ直接ご報告するため）。誤って全員配信にしないよう、
> **必ず特定のグループIDへ push** する作りにしてあります。

1. **Messaging API を有効化**
   - LINE Official Account Manager → 設定 → Messaging API → 利用する
   - 紐づける（または新規作成する）プロバイダーを選ぶ
2. **チャネルアクセストークン（長期）を発行**
   - LINE Developers コンソール → 対象チャネル → Messaging API 設定
   - 「チャネルアクセストークン（長期）」を発行 → `CONFIG.LINE.channelAccessToken` に貼る
3. **公式アカウントをクライアント様グループに招待**
   - クライアント様とのグループに、Add one の公式アカウントを追加
4. **グループIDを取得**（少し技術的なので、必要なら伴走します）
   - Messaging API 設定で Webhook を一時的に有効化し、グループの発言を受けて
     `source.groupId`（`Cxxxxxxxx...`）を確認する等で取得
   - `CONFIG.LINE.to` に貼る
5. `CONFIG.LINE.enabled` を **`true`** にして保存
6. `testNotify` を実行 → クライアント様グループにテストが届けば完了

> グループID取得はつまずきやすいので、ここまで来たら
> 「LINEのグループID取得を手伝って」と声をかけてください。1つずつご案内します。

---

## 困ったとき
- 通知が来ない → CONFIG の見出し名がシートと一致しているか／トリガーが作られているか
- 企業名などが「(空欄)」になる → `HEADERS` の見出し名がズレています
- エラーメールが来た → 本文に原因が出ます。分からなければそのまま共有してください
